The model

Four transaction stages close four different failure modes.

01 PLAN See the complete prospective graph and analyze every change. prevents blind transitives
02 APPROVE Name the exact script or coverage exception that needs authority. prevents broad bypasses
03 APPLY Replay the planned request with package scripts suppressed. prevents pre-review execution
04 VERIFY Compare the observed graph and project checks with the plan. prevents silent drift

No complete analysis means no confident ALLOW.

A truncated graph or an unanalyzed changed package becomes NEEDS_APPROVAL. Coverage is reported as part of the decision rather than implied.

Problem 03 · Local bypass

A local guard can be bypassed. The pull request still needs proof.

GUIDANCE Teach the safe loop Instructions and agent setup make the intended path obvious. can be ignored
INTERCEPTION Mediate package-manager commands Shims cover npm, pnpm, Yarn, Bun, npx, bunx, exec, dlx, ci, rebuilds, and global installs. absolute paths and containers can bypass it
VERIFICATION Refuse the pull request without a valid receipt warden ci --require-transaction-receipt does not trust the developer machine
dependency graph changed→receipt verifies→MERGE
PATH shims are convenience, not a sandbox. The CI receipt requirement catches dependency changes made outside the local Warden path.

Problem 04 · Reputation

A trusted package name says nothing about this release's code or source.

PUBLISHED PACKAGE resolve → integrity → release diff → AST scan → name intel → deterministic score

Finds known malware, name attacks, new execution, provenance changes, credential access, egress, destructive calls, and obfuscation combined with capability.

LOCKFILEWhere will bytes come from?Off-registry hosts, plaintext transport, weak integrity, git and file sources.
SCRIPTSWhat code runs during install?Lifecycle hooks across the installed graph, including pipe-to-shell and credential access.
CONFIGWhere will credentials be sent?Lookalike registries, plaintext tokens, and disabled TLS without echoing secret values.

warden check is deterministic. Verdicts are cached by tarball integrity and analyzer version, so repeat checks stay fast without reusing stale analysis.

Capability signals alone do not automatically mean malware. Behavioural deltas, known malicious versions, name attacks, reverse shells, and environment exfiltration retain their blocking weight.

The invoked manager, packageManager field, lockfile, project config, and PATH decide which tool Warden preserves.

Warden compiles a manager-neutral policy into native npm, pnpm, Yarn, and Bun settings. It does not pretend every manager exposes the same controls.
